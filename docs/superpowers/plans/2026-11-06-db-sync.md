# DB Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Windows desktop app that overwrites a local PostgreSQL or MySQL/MariaDB database with a copy of a development database, in one click and one confirmation.

**Architecture:** An Electron main process owns all database, file and process access. A generic sync runner drives five steps through an engine adapter interface, with one adapter per engine that wraps bundled dump tools. A React renderer talks to main through a small typed preload API and never sees decrypted passwords.

**Tech Stack:** Node 26, TypeScript 7, Electron 45, electron-vite 6, electron-builder 26, React 19, `pg` 8, `mysql2` 3, `yauzl` 3, Vitest 5, Playwright 1.65.

**Spec:** `docs/superpowers/specs/2026-11-06-db-sync-design.md`

## Global Constraints

- Platform: Windows x64 only. Packaging: unsigned NSIS installer.
- The target host must be exactly `localhost`, `127.0.0.1` or `::1`, and `localhost` must resolve only to loopback addresses.
- The source only ever receives read-only queries and dump tools. Its type has no write method.
- Passwords are never passed as command-line arguments and never written to logs. The renderer never receives a decrypted password.
- Tools start with argument arrays and no shell. `contextIsolation` on, `nodeIntegration` off.
- Tests must only connect to database servers they started themselves. A service is already listening on `localhost:5432` on the development machine, and nothing in this plan may connect to it.
- Fixed values: 4 PostgreSQL workers; 5-minute download stall limit; 30-second MySQL/MariaDB `lock_wait_timeout`; last 20 logs per profile.
- Work on branch `feat/db-sync-v1`, created in Task 1. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Do not add anything from the spec's "Out of scope" list.

## Review Focus

Each line has a test in the owning task.

1. **Database names and passwords with special characters**, such as `order-db test` or `p@ss"w\ord'1`: sync works and nothing is misquoted (Tasks 2, 8, 9).
2. **Windows paths with spaces or non-ASCII characters** in `userData` or the install folder: tools still start and dumps still write (Tasks 2, 8, 9).
3. **Row data that looks like SQL**, such as text containing ``DEFINER=`root`@`%` ``, emoji and binary values: copied byte for byte (Tasks 9, 8).
4. **An empty source database, or a first sync when the target doesn't exist:** succeeds, with no backup taken (Tasks 6, 8, 9).
5. **A local Docker database with an empty password, and inherited `PG*` or `MYSQL*` environment variables on the machine:** sync neither hangs on a prompt nor picks up the inherited values (Tasks 2, 8, 9).

```ts
export interface Endpoint { host: string; port: number; user: string; password: string; database: string }

  id: string; name: string; engine: Engine;
  source: SourceEndpoint; target: Endpoint; backupEnabled: boolean;

export interface CheckIssue { severity: 'blocker' | 'warning'; code: string; message: string }
export type TargetState =
  | 'untouched' | 'replaced' | 'restored-from-backup' | 'removed-partial'
  | 'maybe-incomplete' | 'recovery-failed';
export type SyncOutcome =
  | { status: 'success'; durationMs: number; warnings: CheckIssue[];
      targetState: 'replaced' | 'restored-from-backup' | 'removed-partial' } // the last two come from restoreBackup and recover
  | { status: 'cancelled'; targetState: TargetState; backupPath?: string }
  | { status: 'failed'; step: SyncStep; message: string; details: string;
      targetState: TargetState; backupPath?: string };
export type SyncEvent =
  | { type: 'step'; step: SyncStep }
  | { type: 'progress'; label: string; percent: number | null }
  | { type: 'log'; line: string };

type PublicEndpoint<E> = Omit<E, 'password'> & { hasPassword: boolean };
export interface ProfileView {
  id: string; name: string; engine: Engine; backupEnabled: boolean;
  source: PublicEndpoint<SourceEndpoint>; target: PublicEndpoint<Endpoint>;
  lastResult: SyncOutcome | null; hasBackup: boolean; hasUnfinishedSync: boolean;
}
export interface ProfileInput {
  id?: string; name: string; engine: Engine; backupEnabled: boolean;
  source: Omit<SourceEndpoint, 'password'> & { password?: string }; // undefined keeps the stored password
  target: Omit<Endpoint, 'password'> & { password?: string };
}
```

Filter: split into lines on bytes. A line starting with `INSERT INTO` passes through as the original bytes without decoding. Other lines are decoded as UTF-8 and these patterns removed, where `USER` is ``` `(?:[^`]|``)*`@`(?:[^`]|``)*` ```:
